# URL Shortening Service

A production-grade URL shortening service built in Go, designed after the system design in *Grokking the System Design Interview*. The service is split into two microservices — an app server and a Key Generation Service (KGS) — communicating over gRPC.

## Architecture

```
Client
  │
  ▼
Nginx (port 80) — reverse proxy + load balancer
  │
  ├──▶ App Server × 2 replicas (chi router, JWT auth, Redis cache)
  │         │
  │         ├──▶ PostgreSQL (urlshortener DB — URLs + Users)
  │         ├──▶ Redis (URL cache + rate limiting)
  │         └──▶ KGS (gRPC) ──▶ PostgreSQL (keydb — key pool)
  │
  └──▶ KGS (Key Generation Service, gRPC :50051)
            └──▶ PostgreSQL (keydb — unused_keys + used_keys)
```

### Key Design Decisions

| Concern | Decision |
|---|---|
| Key encoding | Base62, 6 chars (62⁶ = 56.8B unique keys) |
| Key generation | Pre-generated by KGS, handed out via gRPC |
| Redirect type | HTTP 302 (preserves analytics) |
| Cache | Redis cache-aside, TTL = URL expiry time |
| Cache eviction | LRU, 256mb limit |
| Rate limiting | Token bucket in Redis — 10 req/min anon, 60 req/min registered |
| Auth | JWT (24h expiry), bcrypt (cost 12) |
| Custom aliases | Scoped per user (`<user_prefix>-<alias>`) — two users can share the same alias |
| Expiry | 30 days anon, 2 years registered |
| Cleanup | Lazy delete on access + background sweep every hour |
| Analytics | Async hit counter (non-blocking redirect), hybrid stats endpoint |

## API Reference

### Auth

**POST /api/v1/auth/register**
```json
{ "name": "alice", "email": "alice@example.com", "password": "secret123" }
```
Returns: `{ "token": "...", "name": "alice", "email": "alice@example.com" }`

**POST /api/v1/auth/login**
```json
{ "email": "alice@example.com", "password": "secret123" }
```
Returns: `{ "token": "...", "name": "alice", "email": "alice@example.com" }`

---

### URLs

**POST /api/v1/shorten**

Works for anonymous users and authenticated users. Rate limited: 10 req/min (anon), 60 req/min (registered).

```json
{
  "long_url": "https://example.com/very/long/path",
  "custom_alias": "mylink",
  "expire_at": "2027-01-01T00:00:00Z"
}
```

- `custom_alias` — optional, requires a JWT token, 3–16 alphanumeric chars, scoped to the user
- `expire_at` — optional RFC3339 timestamp, defaults to 30 days (anon) or 2 years (registered)

Returns:
```json
{
  "short_url": "http://localhost/AbCd3f",
  "hash": "AbCd3f",
  "expires_at": "2026-09-28T00:00:00Z"
}
```

**GET /{hash}**

Redirects to the original URL (HTTP 302). Returns 404 if not found or expired. Increments hit count asynchronously.

**GET /api/v1/stats/{hash}**

Public response:
```json
{
  "hash": "AbCd3f",
  "hit_count": 42,
  "created_at": "2026-08-29T10:00:00Z",
  "expires_at": "2026-09-28T10:00:00Z"
}
```

Owner response (with JWT of the URL creator):
```json
{
  "hash": "AbCd3f",
  "hit_count": 42,
  "created_at": "2026-08-29T10:00:00Z",
  "expires_at": "2026-09-28T10:00:00Z",
  "original_url": "https://example.com/very/long/path"
}
```

**GET /health**

Returns 200 OK. Used by Docker and Nginx health checks.

## Running Locally

### Prerequisites

- Docker + Docker Compose
- [golang-migrate](https://github.com/golang-migrate/migrate) CLI

```bash
brew install golang-migrate
```

### 1. Configure environment

```bash
cp .env.example .env
```

Edit `.env` and fill in:
```
POSTGRES_PASSWORD=your_password
JWT_SECRET=your_jwt_secret
BASE_URL=http://localhost
```

### 2. Start infrastructure and run migrations

```bash
# Start only Postgres first (migrations need it)
docker compose up -d postgres

# Run migrations
migrate -path migrations/urlshortener \
  -database "postgres://postgres:<password>@localhost:5432/urlshortener?sslmode=disable" up

migrate -path migrations/keydb \
  -database "postgres://postgres:<password>@localhost:5432/keydb?sslmode=disable" up
```

### 3. Start the full stack

```bash
docker compose up --build
```

This starts: Postgres, Redis, KGS, 2 × App Server, Nginx.

All traffic goes through Nginx on **port 80**.

## How the KGS Works

The Key Generation Service pre-generates Base62 keys and hands them out safely to app servers over gRPC.

1. **Startup** — KGS checks the `unused_keys` count. If below the threshold (10,000), it generates keys in batches and inserts them (skipping any already in `used_keys`).
2. **In-memory pool** — KGS loads a batch of 1,000 keys into memory and immediately marks them as used in `keydb`. This means a KGS crash never causes duplicate key assignment — every loaded key is already marked used.
3. **GetKey RPC** — app server calls KGS, which pops a key from the in-memory pool under a mutex lock.
4. **ReturnKey RPC** — if a URL is deleted or expired (and wasn't a custom alias), the hash is moved back from `used_keys` to `unused_keys`.
5. **Background top-up** — a goroutine runs every 5 minutes and seeds more keys if the pool runs low.

---

## Cache-Aside Pattern

On every redirect (`GET /{hash}`):

1. Check Redis for `url:<hash>`
2. **Cache hit** → return immediately, increment hit count async
3. **Cache miss** → query Postgres, write result to Redis with TTL = `time.Until(expiresAt)`, increment hit count async

The cache TTL matches the URL's expiry so a cache entry never outlives its URL. Redis is configured with `allkeys-lru` eviction — hot URLs stay in memory, cold ones fall out.

---

## Rate Limiting

Implemented as a **token bucket** using an atomic Lua script in Redis, applied to `POST /api/v1/shorten`.

- Tokens refill gradually at `limit / 60` per second
- Registered users: keyed by `rl:user:<user_id>`, 60 req/min
- Anonymous users: keyed by `rl:ip:<ip>`, 10 req/min
- Redis failure fails open — a Redis outage does not block shortening

---

## URL Expiry

**Lazy delete** — on redirect, if the URL is found expired: delete from Postgres, evict from Redis, return the KGS key to the pool, return 404.

**Background sweep** — a goroutine runs every hour, bulk-deletes all expired URLs, evicts them from Redis, and returns KGS keys to the pool. Custom alias hashes are excluded from key recycling.
